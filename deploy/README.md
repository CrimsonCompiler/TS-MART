# Deploying ts-mart

This is a production-ready Express + EJS + Mongoose app. Target deployment is a container-friendly PaaS (Render, Railway, Fly.io) with **MongoDB Atlas** as the database.

## 1. Provision MongoDB Atlas

1. Create a free cluster at https://cloud.mongodb.com (M0 is fine for demos).
2. **Database Access → Add New Database User** — pick a username + autogenerated password. Copy the password somewhere safe; you won't see it again.
3. **Network Access → Add IP Address** — for the demo, `0.0.0.0/0` (allow from anywhere). For production, restrict to your PaaS's outbound IP range.
4. **Database → Connect → Drivers** — copy the SRV connection string. It looks like:
   ```
   mongodb+srv://USER:PASS@cluster0.abcd.mongodb.net/ts-mart?retryWrites=true&w=majority
   ```
5. Replace `USER` and `PASS` with the credentials from step 2. URL-encode any special characters in the password (`@` → `%40`, `:` → `%3A`, etc.).

## 2. Generate a session secret

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Copy the 64-hex-char output. The server refuses to start without it.

## 3. Deploy

### Option A — Render (Blueprint)

1. Push this repo to GitHub.
2. In Render, **New → Blueprint Instance**, point at the repo. Render reads `render.yaml` and creates the service.
3. In the service's **Environment** tab, paste your `MONGODB_URI` from step 1. `SESSION_SECRET` is auto-generated.
4. First deploy takes ~3 minutes. Watch the logs for `TS-Mart running on port 3000` and `MongoDB connected: mongodb+srv://***@cluster0…`.
5. Once live, hit `https://<your-service>.onrender.com/healthz` — expect:
   ```json
   {"ok":true,"uptime":4,"mongo":"connected","timestamp":"…"}
   ```

### Option B — Docker locally (smoke test)

```bash
cp .env.example .env
# Edit .env — set MONGODB_URI and SESSION_SECRET
docker build -t ts-mart .
docker run -p 3000:3000 --env-file .env ts-mart
curl http://localhost:3000/healthz
```

## 4. Post-deploy smoke checklist

- [ ] `/healthz` returns `{"ok":true,…}`
- [ ] Homepage loads (Tailwind styles apply; logo + nav visible)
- [ ] Place a test COD order end-to-end:
  1. Add a product to cart from `/`
  2. Open `/cart`, click "Proceed to checkout"
  3. Fill in customer form with valid BD mobile + a real-looking address
  4. Click "Place order" — redirected to confirmation page with an order number
  5. Visit `/track/<order-number>` — see timeline render
- [ ] Open MongoDB Atlas → `ts-mart.orders` collection — your test order is there
- [ ] Open `ts-mart.sessions` collection — a session document exists (proof that `connect-mongo` is wired correctly)

## 5. Operational notes

### Graceful shutdown
`server.js` traps `SIGTERM` (sent by Render / Railway / Docker on stop) and `SIGINT` (Ctrl+C). It closes the HTTP server, drains in-flight requests, then closes the Mongo connection. Hard timeout at 10 seconds.

> Note: graceful shutdown cannot be fully tested on Windows — Node on Windows treats `process.kill(pid, 'SIGINT')` as a hard kill and doesn't deliver it to handlers. On Linux (any container or PaaS) the signal is delivered normally and the handler runs. To test locally on Linux/macOS, just press Ctrl+C in the terminal running `npm start`.

### Logs
- `console.log` / `console.error` only — no log library yet. The Mongo URI is automatically redacted before logging (see `redactMongoUri` in `server.js`).
- For high-traffic deployments, pipe stdout to a structured log sink (Render → Logtail, Railway → LogDNA, Fly → Logflare).

### Sessions
Stored in the `sessions` collection of your Mongo DB via `connect-mongo`. Default TTL is 1 day, matching the cookie `maxAge`. Sessions survive restarts.

### Rate limits
- Global: 200 req / minute / IP (skips `/healthz`)
- Checkout submit: 5 req / minute / IP
- Cart writes: 30 req / minute / IP

Behind a proxy on Render/Railway/Fly, the app sets `trust proxy = 1` so the limiter sees the real client IP.

### CSRF
Every mutating form (`/cart/add`, `/cart/update`, `/cart/remove`, `/checkout/submit`) requires a hidden `_csrf` input. Tokens are minted on every page load via `req.csrfToken()` and bound to the session. Missing / wrong token → 403 with a friendly "Session expired" message.

### Security headers
Helmet sets HSTS (1y, preload, includeSubDomains), `Referrer-Policy: no-referrer`, `frame-ancestors 'none'`, and a tight CSP. `X-Powered-By` is disabled.

### Known limitations
- **Tailwind Play CDN** is loaded from `cdn.tailwindcss.com` at runtime. It works but ships ~300 KB of JIT compiler on first paint. For high-traffic deployments, replace with a built stylesheet (Tailwind CLI / PostCSS pipeline); drop `cdn.tailwindcss.com` from the CSP `scriptSrc` in `app.js` when you do.
- **In-memory rate limiter** survives one process. If you horizontally scale, swap `express-rate-limit` for `rate-limit-mongo` or `rate-limit-redis`.
- **Sessions in the same DB as orders** — fine for small shops. For larger scale, set `MONGO_SESSION_URI` to a dedicated cluster.

## 6. Local development

```bash
cp .env.example .env
# SESSION_SECRET=  (paste a 32+ char string)
npm install
npm run seed          # populate the shop with demo products
npm run dev           # nodemon server.js
```

Open http://localhost:3000.

Tests: `npm test` (unit + integration). Coverage: `npm test -- --coverage`.
